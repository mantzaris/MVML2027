# Stage receipt input guard amendment

Recorded before real detector fitting and held-out inference. The previous horizon receipt schema bound commands and output bytes but did not bind stage inputs. Its synthetic-training adoption condition checked only three `best.pt` files; a power failure after an early best epoch could therefore have made unfinished training appear complete.

`run_research.py` now requires complete native synthetic receipts for every seed and verifies the exact three-epoch history, configuration, scene fingerprint, source fingerprint, completed optimizer-step count, and checkpoint payload digests. A best checkpoint alone is insufficient. Existing flow, synthetic feature, and supplemental training adoption similarly checks native configuration, source, completion, and artifact evidence. Cache stages without an existing horizon receipt run their native resumable command instead of trusting a bare status file.

New horizon receipts contain SHA-256 signatures for each stage's command, resolvable recursive project imports, literal source-fingerprint dependencies, relevant configuration, upstream data indices, and model weights. Source, configuration, input, command, or output changes make continuation fail with an explicit audit requirement. Inputs are checked again before committing completion. Generator configuration is scoped to its three actual configuration fields, so unrelated policy settings do not invalidate completed generator training. Dependency locks and the project environment script are also pinned.

The five pre-amendment horizon receipts are migrated only after their native evidence passes. Exact original receipt bytes are retained under `runs/stages/migration_originals/`, with their digest and historical completion time preserved. Migration records distinguish historically recorded core provenance from broader dependencies first pinned at migration; they do not retroactively assert nonexistent source hashes. The old GPU receipt proves observed identity only; every GPU child independently revalidates the exact Ada device through `run_on_ada.py`.

Metadata-only validation passed for all five existing stages. Four regression fixtures passed: incomplete epoch history is rejected; changed source/configuration is rejected despite unchanged outputs; changed outputs are rejected; and migration preserves exact original receipt bytes. These guards do not change trained parameters, features, experiments, or outcome analysis. Native optimizer/RNG checkpoint recovery remains validated separately in `training_resume_amendment.md` and the CUDA resume manifests.
